Queue schema 3 adds an explicit `CreationIdentity` to an incomplete private artifact receipt. It carries the exclusive newly created file's Windows identity and an empty hash; incomplete bytes cannot enter the completed-content inventory, conflict with a chunk/final receipt, or carry a simultaneous promotion identity. `WriteRecordedAsync` saves this receipt before invoking the writer and replaces it with the completed checksum while retaining the same handle. Startup/retry, output preparation and explicit removal retire only the original incomplete file by identity; an absent file retires the stale intent, while a replacement is preserved with an inspection error. Cache cleanup skips pending write/rename jobs, and backup/restore refuses pending identities until reconciliation in the original workspace because copying would change file identity. Earlier schema runtimes are fenced by version 3; existing 0–2 queues retain their payloads and get a verified original snapshot and continuous migration history. The initial create-to-identity-checkpoint window still requires inspection after abrupt loss, and provider/normalizer/encoder/audition do not yet use this durable creation protocol. Completed files continue to require matching content receipts; no partial is reused as valid audio.

The speech adapter creates each response attempt with CreateNew through an exclusive Windows staging handle. That handle stays open across bounded HTTP body retrieval, flush, complete native-PCM validation, reservation settlement and nonoverwriting rename. Valid audio remains private until the reservation is confirmed retired; cancellation and the synthesis deadline are checked again after settlement, before publication. Failed settlement leaves its durable admission fence and removes only the held attempt, allowing explicit retry to reconcile before dispatching again. Handled failure/retry/cancellation removes only the held attempt, without reopening or deleting a pathname. After publication the handle is released and forgotten; cleanup does not reopen its former pathname. An occupied output is preserved and reports a speech-output error; the adapter no longer replaces it. Queue callers continue to prepare tracked outputs through their existing receipt guards. WAV parsing has a leave-open Stream overload so native PCM is inspected through the held handle. No speech contract, fingerprint, schema or persisted fields change. Abrupt host loss before durable private receipt and other incomplete-write ownership gaps remain open.

Audio assembly now creates `assembled.wav` with an exclusive Windows handle and retains that same handle through writing, flush, checksum and the completed-receipt checkpoint. This closes handled assembly failures and the completed-write/receipt handle gap.
